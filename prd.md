# Framework Extractor — Product Requirements

## 1. Product

**Framework Extractor** pulls a teachable framework out of an expert's head. A Creative Director (AI) runs one continuous interview in two phases. Phase 1 extracts the structure in five stages: Anchor, Origin Story, Hypothesis (the 3–7 raw steps), Naming The Steps (Verb + Noun names), Naming The Framework. Phase 2 designs the teaching plan: for every named step, a Story, a Strategy, Tactics and a Case Study, then five scale variants (60-second to multi-day). The output is a Framework Brief the expert can download as Markdown.

It is for experts, coaches and agency founders who already have a method they repeat but have never named it. In the first session a user: (1) creates a project and picks the voice and audience it is written for, (2) answers the Creative Director one question at a time while the framework fills in live on the right, (3) lets the Creative Director draft teaching components they are stuck on, edits any field inline, and downloads the brief.

The repository this PRD ships with is a working prototype of the exact UI and behaviour. Every screen, string, state and the `<fe-state>` contract are implemented; only the AI, persistence and host integrations are mocked. Rebuild it faithfully; do not redesign it.

## 3. Data model

### `framework_project` (user_scoped)

| column | type | example |
|---|---|---|
| title | text | "The Momentum Method" |
| source | text, one of `ai-interview` `voice-note` `brain-dump` `recorded-session` `empty` | "ai-interview" |
| setup | json | `{ "character_id": "ac_1", "voice_id": "v_1", "customer_avatar_id": "av_1" }` |
| state | json | the full `FrameworkProjectState` below |
| archived | boolean, default false (added in PRD, not in prototype) | false |

`id`, `created_at`, `updated_at` are platform-managed; never send them. No hard deletes: Delete sets `archived: true` and the list filters it out.

`state` shape (`src/lib/framework/types.ts` is the source of truth):

```
{
  phase: 1 | 2,
  chat_messages: [{ id, role: "user"|"assistant"|"system", content, created_at, phase_divider?: true, milestone?: 0|1|2|3 }],
  framework: {
    anchor: { niche, dream_customer, single_result } | null,
    origin_story: string | null,
    raw_steps: string[],
    named_steps: [{ from, to }],
    framework_name: string | null,
    framework_tagline: string | null,
    stages: { anchor, origin, hypothesis, naming_steps, naming_framework }   // "pending"|"active"|"done"
  },
  teaching: {
    current_step: number,                     // 1-based
    steps: [{ name, story, strategy, tactics, case_study, components: { story, strategy, tactics, case_study }, evidence?: { story?: "verified"|"illustrative"|"needs_proof", case_study?: … } }],
    scale_variants: { sixty_second, ten_minute, sixty_minute, half_day, multi_day } | null
  }
}
```

Read-only rosters: `CHARACTERS` (id, name, tagline), `VOICES` (id, character_id, name, style_sheet) and `AVATARS` (id, name, tagline) are constants in `src/lib/mock/data.ts` for v1, as are the four `TEMPLATES` (id, name, blurb, anchor). Seed data: the two example projects in that file are demo content for the prototype only; a new account starts with an empty list, which is the correct result.

## 4. Endpoints

### 4.1 `POST /api/ai/framework-chat` — one Creative Director turn (streaming)

Auth required. Input: `{ project_id: string, messages: [{ role: "user"|"assistant", content }], language?: string }`. `messages: []` is the kickoff: the server sends one synthetic user turn so the model greets and asks the first question; it is free (no turn counted).

Behaviour: load the project; refuse with 400 "Message limit reached" when the thread already has 300 user turns; build the system prompt with `buildChatSystemPrompt({ phase, framework, teaching, voiceBlock, language })` from `src/lib/framework/prompts.ts` (the production CHAT_SHELL + the active phase's skill + `buildVoiceAndAudienceBlock` for the picked character (name, tagline, the voice's style sheet) and avatar + the CURRENT STATE snapshot, which carries the "this framework is EMPTY, start from scratch" directive on a new project + the `<fe-state>` protocol + the language pin when not English); stream the model reply as NDJSON lines `{ "type": "delta", "text" }`, then `{ "type": "usage", "credits": 3, "turns_used", "turn_limit": 300 }`, then `{ "type": "done", "stop_reason" }`; on failure `{ "type": "error", "message" }` and stop. Repair round: if the finished reply opens with "Generated …" but `detectGenerationFailure` reports `empty_plan` or `truncated`, send `FE_REPAIR_INSTRUCTION` as a synthetic user turn and splice only the returned `<fe-state>` block into the stream. The client (unchanged from the prototype) strips `<fe-state>` from the visible text, parses the patches with `extractFeStatePatches`, applies them with `applyFeStatePatches`, and autosaves. Model: the most capable Claude model available; max output tokens 8,000; never truncate the block.

### 4.2 `POST /api/ai/framework-regenerate` — rebuild from the transcript

Auth required. Input `{ project_id }`. Replays the persisted `state.chat_messages` (user and assistant only) with `buildRegenerateSystemPrompt({ phase, framework, teaching, voiceBlock })` as the system prompt; expects exactly one `<fe-state>` block; parses it over a fresh initial state; returns `{ phase, framework, teaching }`. 500 with the raw error on any failure; no fallback.


## 5. AI behaviour

5.1 The Creative Director asks ONE question per turn, writes a 1–4 sentence conversational reply, and puts every captured value inside the trailing `<fe-state>` block, never in prose. It proposes candidates in the naming stages (2–3 Verb + Noun names per step; five framework names spanning result-, mechanism- and customer-implying angles) and for Strategy in Phase 2. The full methodology is the two skill bodies in `prompts.ts` (Framework Hypothesis; Teach the Framework). Those texts must be sent verbatim.

5.2 `<fe-state>` is a JSON patch: `framework` keys replace per key, arrays (`raw_steps`, `named_steps`, `teaching.steps`) replace whole, `teaching.step_updates` merge per step by number and name, `stages` / `components` / `scale_variants` merge per key. The client derives all statuses from captured text (`normalizeFramework`, `normalizeTeaching`), so the right pane and the tab dots can never disagree with the data. The Phase 1 → Phase 2 transition turn sets `phase: 2` and seeds `teaching.steps` with one entry per named step. Later teaching turns send only `step_updates`.

5.3 Latency: a normal turn streams for 5–20 s; auto-fill of a step 20–40 s; regenerate 20–60 s. The UI shows the typewriter, the "Generating…" card, and the "Generating…" dots on the auto-filled step's empty components respectively.

5.3b The Creative Director turn that fills the last open teaching component (by answer or by Generate all four) also assembles the five scale variants in the same `<fe-state>` patch and says so ("That completes every step. The brief is ready in Export."). A later message on a complete plan without variants assembles them too.

5.3c The scripted director never invents a factual case study: a drafted case study starts "Illustrative example (replace with a real client before you publish):". Acknowledgements stay short ("Review it on the right, then say when you are ready for the next step."). "I help [who] achieve [result] by [how]" as the first answer parses into the anchor (dream customer = who, result = result, niche = how for who).

5.4 The Framework Brief is built client-side as Markdown by `buildFrameworkBriefMarkdown` in `src/lib/framework/brief.ts`. Sections: name and tagline, Who this is for, What this delivers, Where this came from, The framework (numbered named steps), Step N: name with Story / Strategy / Tactics / Case Study, Scale variants.

## 6. Design

Dark theme by default: three stacked greys and one ocean-blue accent. Tokens (HSL, from `src/index.css`, `.dark`): background `0 0% 7%` (the chat column and the workspace header share it), foreground `0 0% 96%`, card `0 0% 10%` (sidebar, composer card), surface `0 0% 13%` (the output pane, laid over the app like a sheet of paper: top-left corner rounded 16px on desktop, a 1px white/6% hairline and a soft shadow cast to the left onto the chat), popover `0 0% 12%`, primary `199 89% 48%` (ocean blue) with primary-foreground `0 0% 100%`, secondary / muted `0 0% 15%`, muted-foreground `0 0% 62%`, accent `0 0% 17%`, border / input `0 0% 19%`, ring `199 89% 48%`, destructive `0 72% 51%`, `--radius: 0.5rem`. The brand icon in the sidebar is a dark tile (background colour, hairline border), not the accent. Fonts: display Sora, body Figtree. Status colours: done = emerald-500, active = primary, pending = muted-foreground. No OverSkill badge, no avatars in the chat, no coloured icon tiles. Primary buttons are slightly three-dimensional: a top-to-bottom gradient from `--primary` to `--primary-deep: 199 89% 36%`, a 1px border in the deep shade, a 1px white inset highlight on top, a soft primary-tinted drop shadow, and on press a 1px downward shift with an inset shadow; `--primary-bright: 199 89% 54%` on hover. Other buttons press with `active:scale-[0.96]`. Numbers use `tabular-nums`. Components: shadcn `Button`, `Input`, `Select`, `DropdownMenu`, `AlertDialog`, sonner toasts, lucide icons. Match `public/screenshot.jpg` (the workspace) and the prototype's rendering exactly.

## 7. Out of scope for v1

- Credit balance display and deduction; the "3 credits / reply" and "20 credits" labels stay as static copy, the 300-message cap is enforced.
- Team Brain facts, work-context pulls, replies in languages other than English.

- Light theme.
- PDF and slide exports, export scopes, an asset hub / hand-off to MarketingSecretsAI tools, a "Created from this framework" history, framework versions (files are v1), writing new facts back to the Brain.

## 8. Constraints

Fail fast, no silent catches. Compare all ids with `String(a).trim()===String(b).trim()`. No client-supplied ids into `create()`. Identity from `getAuthContext` only, never from the request body. No hard deletes anywhere; use status/revoked/archived flags. Do not add client-side pruning: a local row absent from a server response must never be deleted; absence means unknown. Never rewrite a file over 200 lines from memory; use targeted edits. Report the full deployed source of all touched endpoints, client diffs, and an explicit not-done list. When I say an empty result is correct, do not seed data.
